# Оценка поведения и расхода

## Автоматические проверки контракта

```sh
python3 scripts/evaluate.py --output evaluation-report.json
# Дополнительно — read-only проверка доступности native процесса:
python3 scripts/evaluate.py --output evaluation-report.json --native-server ./bin/codex-vision-darwin-amd64
```

Нужны Go 1.26.5+ и Python 3.11+. Скрипт не вызывает LLM, не отправляет формы и не управляет приложениями. Он запускает парные **синтетические** сценарии:

| Сценарий | Что проверяется |
| --- | --- |
| browser_like | Наблюдение, выбор известного контрола, UI-условие и итоговый кадр |
| form_like | Единый снимок полей, пакет заполнения и UI-условие |
| terminal_like | Разрешённая клавиша и наблюдаемая смена состояния |
| cad_like | Контрол, локальное ожидание и изображение для следующего решения |

Сравниваются отдельные инструменты и единый цикл на одинаковом scripted fixture. В JSON есть вызовы, изображения, объём результатов, ошибки, принятые действия и локальное elapsed time. Скрипт откажется сообщать успех при неполном наборе сценариев или увеличении числа вызовов/изображений в unified-варианте.

Это проверка драйвера и протокола, **не** тест реальных сайтов, команд, FreeCAD, игрового движка или качества выбранной модели. Ноль `scripted_manual_interventions` означает только, что сценарий scripted. Native `--doctor` — preflight, а не проверка кликов; `blocked` или `preflight_only` не превращаются в успешную GUI-проверку.

## Одинаковые задачи для проверки через Codex

Проверяйте в своей разблокированной GUI-сессии, на тестовых данных и с точным allowlist. Для начала и конца каждого прогона сохраните `session_status.metrics`; вручную запишите вмешательства и фактический результат. Не публикуйте снимки с личными данными, audit или preview URL.

Для локального browser-fixture:

```sh
python3 -m http.server 8766 --bind 127.0.0.1 --directory eval/fixtures
```

Откройте `http://127.0.0.1:8766/` в разрешённом браузере. Сервер страницы завершите после проверки.

| Проверка | Задача | Критерий успеха |
| --- | --- | --- |
| Браузер | Открыть и закрыть Test dialog | Диалог действительно появился и исчез, ввод попал в нужное окно |
| Форма | Заполнить Name/Email/City тестовыми значениями и нажать Save form | Поля соответствуют данным, заголовок стал Form saved; страница ничего не отправляет в сеть |
| Пошаговый UI | Нажать Next turn и дождаться нового противника | На итоговом кадре Alpha сменился на Beta; часы не вызывают бесконечную выдачу кадров |
| Terminal | Выполнить безвредный вывод `codex-vision-eval`, не трогая открытые SSH-сессии | Строка видна в нужной тестовой сессии, дополнительных команд нет |
| FreeCAD | В новом несохранённом документе создать Box и показать его целиком | Box существует в дереве и виден, исходные документы не изменены |
| Восстановление | Между observe и act активировать другое разрешённое приложение | Не более одной focus-попытки; без ввода в неправильное окно |
| Устаревший элемент | Между observe и act изменить расположение контрола | Действие остановлено как stale, старый пакет не повторён |

Для терминала создайте отдельное локальное тестовое окно: не используйте вкладку, подключённую к реальному серверу. В FreeCAD не сохраняйте поверх существующих документов. Новую реальную партию с человеком для этой проверки не запускайте: локального fixture или бота достаточно.

## Как сравнивать модели и версии

Фиксируйте ОС, версию сервера, модель, reasoning mode, задачу, исходное состояние, разрешения, размеры области и параметры наблюдения. Выполните несколько одинаковых прогонов. Запишите отдельно:

- фактическое достижение цели;
- ошибки/неправильные действия;
- число ручных вмешательств;
- MCP-вызовы и изображения;
- локальное время и полное время задачи;
- реальное usage клиента, если он его показывает.

Число картинок, raw bytes и проценты оставшейся подписки не взаимозаменяемы. Маленький scripted benchmark не доказывает экономию на любой задаче и не показывает, что другая модель стала равна Astra.
