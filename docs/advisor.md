# Vision Coach — подсказки на экране

С версии 0.14.0 `advisor` показывает рекомендации в локальной браузерной панели. Модель анализирует выбранную область, публикует краткий совет и продолжает наблюдение. Пользователь выполняет ходы самостоятельно. Пока советник активен, MCP блокирует инструменты ввода, включая переключение окон; `advisor stop` явно завершает этот режим. Аварийная остановка остаётся доступной.

## Запуск

После сборки/обновления перезапустите MCP и проверьте `session_status.server.version`. Затем можно написать агенту:

> Включи режим советника для открытой игры. Сначала найди и активируй игру, получи кадр только области боя. Запусти advisor и покажи ссылку панели. Сам не делай ходов. Наблюдай за значимыми изменениями; публикуй короткую рекомендацию, причину и альтернативу через advisor. Не останавливай советник, чтобы вернуть себе ввод. Не вызывай session_stop для завершения наблюдения.

Последовательность MCP:

1. `window_list` → при необходимости `window_focus` → `desktop_observe` с выбранным `watch_region`.
2. `advisor {"action":"start","view_id":"...","title":"Pokeworld · Советник"}` возвращает `advisor_url`.
3. Откройте ссылку на **этом компьютере**, выберите «Поверх игры», затем верните фокус игре. Разместите панель за пределами наблюдаемой области; она не должна закрывать кнопки и данные боя.
4. Для свежего изображения вызывается `advisor publish`, затем агент продолжает scoped observe/publish. Никаких промежуточных автоматических кликов.

```json
{
  "action": "publish",
  "view_id": "VIEW_FROM_OBSERVATION",
  "recommendation": "Сохрани покемона и сделай защитную смену",
  "reason": "По текущему кадру соперник угрожает сильной атакой. Смена сохранит ресурс для следующего хода.",
  "alternative": "Если ожидаешь смену соперника, можно сохранить инициативу быстрой атакой.",
  "urgency": "important",
  "ttl_seconds": 20
}
```

Это пример формата, а не игровая рекомендация для реального боя. Необходимы подтверждённые данные о противнике, приёмах и состоянии; качество решения определяется моделью и имеющейся информацией. `urgency`: normal / important / critical. Лимиты текста: 240 / 600 / 300 символов. TTL: 3..120 секунд, по умолчанию 20. Проценты уверенности не генерируются сервером.

## Окно и уведомления

- Полноценная панель для второго экрана и компактный режим для небольшой области. Светлая, тёмная и системная темы; управление клавиатурой, видимый фокус и reduced-motion.
- «Поверх игры» использует Document Picture-in-Picture при наличии API; иначе открывает обычное отдельное окно. PiP подтверждён браузерным тестом, но не тестом реальной игры. Он **не пропускает клики насквозь**. Над эксклюзивным полноэкранным режимом игры показ не гарантирован; используйте оконный/безрамочный режим.
- «Важные события» по явному нажатию запрашивает разрешение на системные уведомления на **этом устройстве**. Уведомления только для important/critical, без звука и без запроса фокуса. Предыдущее заменяется, при устаревании закрывается. Режим фокусировки ОС и браузер могут подавить их.
- Одинаковая рекомендация для той же версии кадра не обновляет TTL и не вызывает повторное уведомление.
- «Пауза» приостанавливает публикацию подсказок, сохраняя запрет ввода. После «Продолжить» старая рекомендация не возвращается; требуется новая публикация. Захват экрана этим переключателем не останавливается.
- Сеть и телефон не используются. Панель слушает только случайный loopback-порт, без облаков, аккаунтов, внешних шрифтов и аналитики. В ней нет изображения экрана и удалённого управления.

## Актуальность и ограничения

Публикация требует действующего `view_id`, доставленного изображения, совпадения observation ID / sequence / focus version / области и подтверждения окна. Статус stale выставляется после значимого изменения кадра, смены области, потери фокуса игры, паузы/остановки наблюдения или истечения TTL. Потеря фокуса проверяется при локальном захвате; возвращение в игру не оживляет прежний совет. Это проверка привязки к кадру, **не семантическое распознавание хода**. Во время анимации/смены противника нужно дождаться нового анализа.

Панель необходимо держать вне `watch_region`. Автоматическое исключение браузерного PiP из native capture не реализовано: если окно подсказки закрывает область боя, его пиксели тоже попадут в захват. Для игры на одном мониторе выберите меньшую область с противником/здоровьем/приёмами и поставьте панель сбоку. Внешние оверлеи в правилах конкретной игры проверяются отдельно.

Локальные обновления панели не вызывают LLM и не потребляют MCP-действия. Но экран по-прежнему анализирует агент по вызовам: нужен активный цикл наблюдения/публикации. Фоновый поток не запускает модель самостоятельно, работа с другой задачей не создаёт параллельного игрового советника. Встроенной локальной игровой модели нет. Скорость и расход лимита зависят от модели, числа значимых кадров и выбранной области; 148-секундный бой не гарантируется.

`advisor stop` закрывает панель и снимает блокировку ввода, но не вызывает `session_stop` и не останавливает захват. В конце задачи отдельно используйте `observation_control stop`. Закрытие браузерного окна не завершает режим советника автоматически.

Windows / macOS / Linux используют одну Go-реализацию и встроенные HTML/CSS/JS. Захват экрана зависит от native backend и его разрешений; Linux Wayland этим изменением не добавлен. Поддержка PiP и системных уведомлений зависит от браузера, поэтому универсальный native overlay не заявляется.

## Приватность и проверка

Ссылка содержит случайный 256-bit ключ во фрагменте `#...`; он не отправляется в HTTP URL/Referer. Страница убирает фрагмент и держит ключ в памяти/sessionStorage вкладки. `/state` и `/control` требуют Bearer, проверяются Host и Origin; UI не умеет публиковать советы или выполнять действия. Текст выводится через textContent. В памяти хранится только текущий совет; история советов не записывается на диск.

Go-тесты проверяют stale/TTL, потерю фокуса, запрет ввода, завершение режима без остановки сессии, токен, Host/Origin, методы, размеры и подмену источника. При запрете bind в sandbox HTTP-контракт проверяется in-memory listener/httptest, что не заменяет реальный listen.

Браузерная проверка проведена на синтетических данных: ширины 320/375/768/1024/1280/1920 без горизонтальной прокрутки, светлая/тёмная тема, reduced-motion, клавиатура, компактный режим с возвратом, PiP под production CSP, пауза, stale, безопасный вывод HTML-подобного текста и закрытие прежнего уведомления. Notification в тесте заменён mock, реальные уведомления ОС и настоящая игра не тестировались. Lighthouse/axe не установлены; баллы этих инструментов и ручная проверка VoiceOver/NVDA не заявляются. Панель намеренно noindex, без публичного SEO. JS около 4 КБ gzip, CSS около 3 КБ gzip; новых зависимостей нет.

Для отдельного браузерного smoke-теста с **синтетическими** подсказками на разрешённом loopback:

```sh
CODEX_VISION_ADVISOR_PREVIEW=1 go test ./internal/advisor -run '^TestAdvisorUIPreview$' -v -count=1 -timeout=12m
```

На Windows в PowerShell задайте `$env:CODEX_VISION_ADVISOR_PREVIEW='1'`, затем выполните ту же команду `go test`. Тест печатает временную ссылку; его можно остановить Ctrl+C. Он не наблюдает за настоящей игрой и не вызывает модель.
