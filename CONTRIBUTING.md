# Разработка Codex Vision

## Рабочий цикл

1. Создайте ветку для изменения.
2. Изменяйте соответствующий слой: MCP-протокол, наблюдение, политику или backend.
3. Проверьте поведение и ограничения; добавляйте тест, если он подтверждает важное поведение, а не повторяет реализацию.
4. Обновите документацию при изменении аргументов, defaults или разрешений.
5. Опишите изменение и фактическую проверку в pull request.

Нужны Go 1.26.5+; для native macOS — CGO и Apple SDK. Python 3.11+ требуется только скрипту регистрации и его тестам.

```sh
go test ./...
go vet ./...
python3 -m unittest discover -s scripts -p 'test_*.py'
```

Проверку гонок запускайте отдельно:

```sh
go test -race ./...
```

## Что проверяют тесты

Переносимые тесты используют mock/synthetic desktop и проверяют схемы MCP, локальную политику, координаты, наблюдение, ожидания и отмену. Часть macOS-тестов компилирует небольшие Objective-C fixtures. Им не нужен доступ к вашему рабочему экрану.

`./scripts/test.sh --native` включает opt-in native integration проверки. Запускайте их только в подходящей локальной разблокированной GUI-сессии с разрешениями ОС. Это не доказательство совместимости каждого приложения. Проверки в sandbox могут пропускать возможность loopback-bind; такой skip не следует выдавать за проверенный preview в браузере.

GitHub Actions запускает Go-тесты и vet на Linux, macOS и Windows, отдельные race-проверки и сборки. CI не проверяет клики в реальном пользовательском приложении.

## Перед публикацией

- Не добавляйте личные конфиги, токены, снимки, preview-ссылки и audit-файлы.
- Публикуйте переносимые примеры, не списки приложений конкретного компьютера.
- Не ослабляйте проверку foreground/allowlist ради исправления координат.
- Сохраняйте stop, отмену и запрет автоматического повтора частично выполненных действий.
- Обновление бинарника требует перезапуска запущенного MCP; проверяйте `session_status.server.version`.
